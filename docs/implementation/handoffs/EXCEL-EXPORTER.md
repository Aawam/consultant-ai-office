## Implemented architecture

`office-web → office-runtime → ExportRabExcelUseCase → RabWorkbookExporterPort / ArtifactStoragePort → ExcelJS / local artifact file`.

Authorization and lifecycle checks are in Application Layer. REVIEW and FINAL require the persisted calculation snapshot. The exporter does not query the database or live master data directly.

## Implemented behavior

- Working export: TECHNICAL or ADMIN, DRAFT or REVIEW; workbook visibly carries `NOT OFFICIAL`.
- Official export: ADMIN and FINAL only; workbook carries official state and RAB version identity.
- Artifact filenames include project, RAB version, export type, and unique artifact ID; prior official artifacts are not overwritten.
- Workbook contains `PROJECT`, `REKAP`, `RAB_DETAIL`, `BV`, `HSP_USED`, `AHSP_COMPONENTS`, `RESOURCE_SNAPSHOT`, `HSP_MAPPING`, and `CHECKS`.
- Tables, structured-reference formulas, defined names, sheet protection, full-recalculation-on-open, and no macro/external-link generation are implemented.
- Browser controls call `/api/workflow` and download the actual generated bytes; blocked operations return the Application error.

## Numeric and traceability notes

Critical arithmetic remains in the P1 deterministic engine. The workbook exposes formula chains and uses decimal text for snapshot values. Stable project/RAB/item/HSP/component/resource identifiers are carried where present in the persisted snapshot.

The current persisted Phase 1 model does not yet expose a complete BV line/template snapshot or dedicated artifact database record. The adapter therefore emits the required `BV` table shape but cannot claim full GT-01–GT-12 BV export coverage. Unit canonicalization must also be resolved before export by the source snapshot; Infrastructure does not import the calculation engine.
